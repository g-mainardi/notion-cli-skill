===== ntn api --help
Call the public Notion API (beta)

Usage: api [OPTIONS] [PATH] [INPUT]...
       api [OPTIONS] [PATH] [INPUT]... <COMMAND>

Commands:
  ls    List supported public API endpoints
  help  Print this message or the help of the given subcommand(s)

Arguments:
  [PATH]
          The public Notion API path to call

  [INPUT]...
          Inline request inputs such as headers, query params, and body fields

Options:
  -d, --data <JSON|@PATH|@->
          Use a JSON string, @path, or @- as the request body

  -X, --method <METHOD>
          Override the inferred HTTP method

      --spec
          Print a reduced OpenAPI fragment for the selected endpoint

      --docs
          Print the full official markdown docs for the selected endpoint

      --file <PATH>
          Read the file contents into a multipart `file` form field

      --notion-version <VERSION>
          Override the Notion-Version header
          
          [env: NOTION_API_VERSION=]

  -h, --help
          Print help for `ntn api` or for a specific endpoint

Request Body Sources:
  Use exactly one of these body sources per request:
  - stdin JSON
  - `-d, --data <JSON|@PATH|@->`
  - inline body inputs such as `path=value` and `path:=json`

Request Input Syntax:
  Extra arguments after <PATH> are parsed as inline request inputs.

  Header:Value   Request header                 Accept:application/json
  name==value    Query parameter                page_size==100
  path=value     Body string assignment         parent[page_id]=abc123
  path:=json     Body typed JSON assignment     archived:=true

  Parser precedence:
  1. path:=json
  2. name==value
  3. Header:Value
  4. path=value

  Body paths support nested objects and arrays:
  properties[foo]=bar
  properties[count]:=10
  children[][paragraph][rich_text][0][text][content]=Hello

  Method selection:
  - GET by default
  - POST automatically when stdin JSON, `--data`, or inline body inputs are present
  - -X/--method always wins

  Notes:
  - Use := for numbers, booleans, arrays, objects, and null.
  - Use = to always store a JSON string.
  - Use `--data @body.json` to read JSON from a file.
  - Use `--data @-` to read JSON from stdin as the `--data` source.
  - Body JSON must come from exactly one source: stdin, `--data`, or inline body inputs.

  Shell Completion:
  - PATH completions come from the live or cached OpenAPI spec.
  - -X/--method only suggests methods supported by the selected path.

Environment Variables:
  NOTION_API_BASE_URL         Base URL for public API requests (default varies by --env)
  NOTION_API_DOCS_BASE_URL    Base URL for OpenAPI/docs lookups (default: https://developers.notion.com)
  NOTION_API_TOKEN            Override the token used for authentication
  NOTION_API_VERSION          Notion-Version header to send (same as --notion-version)
  NOTION_ENV                  Environment to target for other CLI commands (same as --env)
  NOTION_HOME                 Override the CLI state root (`ntn api` cache uses NOTION_HOME/cache)
  NOTION_KEYRING              Set to 0 to use file-based auth (~/.config/notion/auth.json) instead of OS keychain
  NOTION_WORKERS_CONFIG_FILE  Path to workers.json config file (same as --workers-config-file)
  NOTION_WORKSPACE_ID         Workspace ID override used by other CLI commands
  XDG_CACHE_HOME              XDG base directory for cached OpenAPI specs (fallback)
  XDG_CONFIG_HOME             XDG base directory for config/auth state (fallback)

===== ntn pages --help
Manage pages

Usage: ntn pages [OPTIONS] <COMMAND>

Commands:
  trash   Trash a page
  get     Retrieve a page as Markdown
  create  Create a page from Markdown content
  edit    Edit a page's content from Markdown
  help    Print this message or the help of the given subcommand(s)

Options:
  -v, --verbose
          Show full error details including source chains

      --workers-config-file <WORKERS_CONFIG_FILE>
          Path to workers.json config file (overrides default CWD lookup)
          
          [env: NOTION_WORKERS_CONFIG_FILE=]

  -h, --help
          Print help (see a summary with '-h')

  -V, --version
          Print version

Scope:
  `ntn pages` supports retrieving, creating, and editing pages as Markdown content.

Examples:
  ntn pages get <page-id>
  ntn pages get <page-id> --json
  ntn pages create --content '# Title\n\nBody'
  ntn pages create --parent data-source:01234567-89ab-cdef-0123-456789abcdef < page.md
  ntn pages create                                                           # opens $EDITOR
  ntn pages edit <page-id> --content '# Updated body'
  ntn pages edit <page-id> < page.md
  ntn pages edit <page-id>                                                   # opens $EDITOR

Notes:
  - `ntn pages get` prints page Markdown with page properties prepended as frontmatter by default.
  - `ntn pages create` and `ntn pages edit` strip a leading frontmatter block from input, so `get` output can be fed back in. On create, a frontmatter `title` sets the page title; other frontmatter properties are ignored.
  - If `ntn pages get` returns truncated Markdown, stderr will suggest using `--json` to inspect `unknown_block_ids`.
  - Provide Markdown with `--content`, stdin, or interactively via `$EDITOR`.
  - `--parent` (create only) is optional: `page:<id>`, `database:<id>`, or `data-source:<id>`.
  - When no content source is given in a TTY, `$VISUAL` / `$EDITOR` / `vi` is opened.
  - For properties, templates, or the full Pages API surface, use `ntn api v1/pages`.

Environment Variables:
  EDITOR                      Editor opened for interactive Markdown editing (fallback: vi)
  VISUAL                      Preferred editor (checked before $EDITOR)
  NOTION_API_BASE_URL         Base URL for public API requests (default varies by --env)
  NOTION_API_DOCS_BASE_URL    Base URL for OpenAPI lookups used to resolve the latest version
  NOTION_API_TOKEN            Public API integration token for authentication (required today for `ntn pages`)
  NOTION_API_VERSION          Notion-Version header to send (same as --notion-version)
  NOTION_ENV                  Environment to target for other CLI commands (same as --env)
  NOTION_HOME                 Override the CLI state root for cache and config
  XDG_CACHE_HOME              XDG base directory for cached OpenAPI specs (fallback)
  XDG_CONFIG_HOME             XDG base directory for config/auth state (fallback)
